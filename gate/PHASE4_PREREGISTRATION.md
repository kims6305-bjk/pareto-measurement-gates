# Phase 4 사전 선언 — 하네스 자동탐색에 다목적 채택 게이트를 붙인다

**상태: 초안(DRAFT). Phase 3 판정 확정 전에 작성했다.**

작성 시점에 Phase 3 저지 실행은 진행 중이고 **결과를 열람하지 않았다.**
이것이 이 문서를 지금 쓰는 이유다 — Phase 3 결과를 본 뒤에 Phase 4를 설계하면
설계 자체가 사후 선택이 되어, Phase 4가 시작도 전에 오염된다.

§2의 분기 규칙은 **결과가 어느 쪽으로 나오든 무엇을 할지**를 미리 고정한다.
Phase 3 종결 후 이 문서를 `DRAFT` 해제하고 §3의 빈 칸(baseline 수치)만 채운다.
**§1·§2·§4·§5·§6은 결과를 보고 수정하지 않는다.**

---

## 0. Phase 3와의 관계

Phase 3는 **진단**이다: "per-claim 채점 결과가 문맥에 따라 체계적으로 달라지는가".
Phase 4는 **개선**이다: "그 진단을 반영한 하네스가 원래 하네스를 지배하는가".

성격이 다르므로 실험도 분리한다. Phase 3의 금지 사항 §7.1(실행 중 프롬프트
자동탐색 금지)은 **Phase 3 실행에 한한 제약**이며, Phase 4에서는 탐색이 오히려
연구 대상이다. 단 Phase 4는 **Phase 3에서 쓴 확증 집합을 학습·탐색에 쓰지 않는다**
(§5.2).

## 1. 문제 정의 — 왜 Phase 4가 필요한가

Stanford IRIS `meta-harness`(MIT, arXiv 2603.28052) 실물 대조에서 확인한 결함:

- `AGGREGATORS`가 전부 `Sequence[float] -> float`. **목적함수가 단일 스칼라**다.
- `update_frontier()`는 이름만 frontier이고 실제로는 best pass_rate 기록판이다.
  **지배(dominance) 판정이 없다.**
- `ONBOARDING.md`는 secondary metrics(latency, context cost, API spend)를 묻지만
  그 답이 최적화 루프로 흘러갈 경로가 코드에 없다. **문서와 구현의 간극.**
- 참조 스킬은 `"You MUST produce 1 new agent variant every iteration.
  Do NOT write 'the frontier is optimal' or 'stop iterating'"`으로 **변이를 강제**한다.

> **P (문제 명제)**: 단일 스칼라 목적함수 + 강제 변이 조합은, 비용축을 태워
> 성능축을 올리는 변이를 **구조적으로 선호**한다. baseline이 이미 프런티어
> 모서리점일 때는 상방이 0이고 하방만 열려 있으므로, 강제 변이는 기대값이 음수다.

이 명제는 우리 데이터에 선례가 있다. probe-graph P1 A/B에서 baseline이
(인용오류 0%, 정확도 99.2%)인 모서리점이었는데 검증 레이어를 얹자
상방 0 + 과교정 −0.84%로 **순수 파레토 열등 이동**이 나왔다.

## 2. 🔴 Phase 3 결과에 따른 분기 (결과 열람 전 고정)

Phase 3가 무엇을 하든 Phase 4는 실행한다. 다만 **탐색 공간이 달라진다.**

| Phase 3 판정 | Phase 4 탐색 공간 | 근거 |
|---|---|---|
| **H1·H2 모두 채택** | 형제 문맥 블록을 변이 후보에 **포함**. 규칙유형별 조건부 문맥도 후보. | 채점 단위 효과가 규칙유형을 구분함이 확증됨 |
| **H1 채택 / H2 미충족** | 형제 문맥은 **후보에 넣되 기본값으로 삼지 않는다.** 게이트가 지배 판정으로만 채택 결정. | "효과는 있으나 진짜 오류도 통과시킬 위험"(§4 사전 해석) |
| **H1 기각** | 형제 문맥을 변이 후보에서 **제외**. 탐색 공간은 문맥 외 축(지시문 구조·근거 제시 순서·판정 스키마)으로 한정. | 이 표본에서 지지되지 않은 처치를 탐색 시드로 쓰면 Phase 3 결론과 모순 |
| **군집화로 판정 불가** | H1 채택/미충족 행과 동일 취급(H2 미충족과 같은 보수적 경로). | 판정 불가는 채택이 아니다 |

**어느 경우에도 Phase 4의 주장은 "형제 문맥이 좋다"가 아니라
"다목적 게이트가 단일 스칼라 게이트보다 나은 채택 결정을 내린다"이다.**
Phase 4의 결과변수는 하네스 성능이 아니라 **게이트의 판정 품질**이다(§4).

## 3. 목적 벡터 (측정 전 고정)

스킬 `pareto-optimization-gate` §0에 따라 **측정 전에** 축과 목표함수를 고정한다.

| 축 | 지표 | 방향 | 측정 방법 |
|---|---|---|---|
| 성능 | 저지 판정 정확도 대비 사람 라벨 | ↑ | Phase 1 라벨 55건(불변 집합) |
| 비용 1 | 프롬프트 문자수 (context cost 대리) | ↓ | 프롬프트 빌더로 **결정론적 재생성** |
| 비용 2 | 콜당 지연 `elapsed` 중앙값 | ↓ | Phase 3 jsonl에 이미 기록 중 |

**비용축을 사후에 정하지 않았다는 증거**: `phase3_run_judge.py`는 Phase 3
실행 전부터 `elapsed`를 기록하고 있었고(코드 L102), 프롬프트 문자수는 빌더가
결정론적이라 사후에도 편향 없이 복원된다. 토큰 카운트는 기록되지 않으므로
**토큰을 비용축으로 쓰지 않는다** — 없는 데이터를 사후에 만들어 붙이지 않는다.

**목표함수: 파레토 지배.** 스칼라 가중합을 쓰지 않는다. 가중치를 정하는 순간
그것이 사후 선택의 통로가 된다.

**baseline** (Phase 3 종결 후 채움):
- 성능: ____
- 프롬프트 문자수 중앙값: ____
- `elapsed` 중앙값: ____

## 4. 결과변수 = 게이트의 판정 품질 (하네스 성능이 아니다)

Phase 4의 주장이 "우리 하네스가 더 좋다"라면, 그건 탐색을 많이 돌린 쪽이
이기는 자명한 결과다. 그러므로 결과변수를 게이트로 옮긴다.

동일한 변이 집합 V(N개)를 생성한 뒤, **두 게이트가 각각 무엇을 채택하는지** 비교한다.

- **게이트 S (대조)**: 단일 스칼라. 성능이 baseline보다 높으면 채택. (meta-harness 재현)
- **게이트 P (처치)**: 파레토 지배. 세 축 모두 baseline 이상이고 하나 이상 초과일 때만 채택.
  지배하지 못하면 `트레이드오프`로 라벨해 보류.

> **H1' (주가설)**: 게이트 S가 채택한 변이 중 **비용축이 악화된 비율**이
> 게이트 P가 채택한 것보다 유의하게 높다.
>
> **H2' (모서리점 가설)**: baseline이 프런티어 모서리점에 가까울수록
> 게이트 S의 채택 중 열등 이동 비율이 증가한다.

H2'가 이 실험의 진짜 값어치다. "다목적이 더 낫다"는 거의 동어반복이지만,
**언제 얼마나 나쁜지**는 실측이 필요하다. 모서리점에서 강제 변이가 왜 위험한지에
정량 근거를 붙이는 것이 목표다.

### 4.1 사전 선언한 판정 기준

**H1' 채택 조건 — 모두 충족**
1. 게이트 S 채택분의 비용축 악화 비율 > 게이트 P 채택분, McNemar 양측 **p < 0.05**
   (같은 변이 집합을 두 게이트로 판정하므로 쌍대)
2. 열등 이동(성능 동률 이하 + 비용 악화)이 게이트 S에서 **1건 이상** 실제 발생
3. 변이 생성이 두 게이트에 **동일한 집합**임이 코드로 검증됨(게이트는 판정만 하고
   생성에 개입하지 않는다)

**H2' 채택 조건**
4. baseline 오류율 구간별(0%, 0~5%, 5%+)로 층화했을 때 열등 이동 비율이
   **단조 감소**하고, 최저·최고 구간의 Wilson 95% 구간이 비겹침

**부분 결과의 해석 (미리 고정)**
- 1~3 충족 + 4 미충족 → **"게이트 차이는 있으나 모서리점 효과는 미확인"**으로 보고.
  강제 변이의 위험성을 정량화했다고 주장하지 않는다.
- 1~3 미충족 → **H1' 기각**. "이 변이 집합에서는 단일 스칼라 게이트도
  열등 이동을 유의하게 더 채택하지 않았다"로 보고한다. 표본을 늘려 재검정하지 않는다.
- N이 부족해 검정력이 안 나오면 **Phase 2처럼 정직하게 판정 불가로 종결**한다.
  이 프로젝트는 이미 그렇게 한 전례가 있고, 그것이 규율이다.

### 4.2 검정력 사전 계산 (실행 전 필수)

**Phase 2의 교훈은 "계산을 안 하면 자원을 태우고 나서 판정 불가를 안다"였다.**
따라서 변이 생성 전에 `phase4_power_check.py`를 작성해 다음을 확정한다.

- McNemar 양측 정확검정 임계: 불일치쌍 **6건**(5건이 아니다 — Phase 3 §3.1 정정 참조)
- 그 6건을 얻는 데 필요한 변이 수 N을 기대 불일치율로 역산
- **N이 현실적 예산을 넘으면 실행하지 않고 그 사실을 보고한다.**

### 4.3 🔴 결과변수 기저율 파일럿 (Phase 3에서 배운 것 — 필수 요건)

Phase 3는 표본 264건을 확보하고도 검정에 실패했다. 조건 A(대조)의 문제 판정이
**0건**이어서 뒤집힐 대상 자체가 없었기 때문이다(`PHASE3_VERDICT.md` §2).
분모는 세었으나 **분자의 기저율을 재지 않은 것**이 설계 결함이었다.

따라서 Phase 4는 변이를 생성하기 **전에** 다음을 실측한다:

1. baseline 하네스에서 **게이트 S와 게이트 P의 판정이 갈릴 여지가 있는지** —
   즉 성능/비용이 baseline과 다른 변이가 실제로 생성되는지를 소규모(N=10)로 확인.
2. 그 10건에서 **불일치가 0건이면 본 실행을 시작하지 않는다.** 기저율 0인
   결과변수로는 어떤 표본 크기로도 검정할 수 없다.
3. 파일럿은 Phase 2와 동일하게 **본 표본에 중첩**시켜 폐기하지 않는다
   (정본 순서를 seed 고정으로 만들고 앞 10건을 파일럿으로 정의).

**이 요건은 Phase 4 결과를 보기 전에 추가됐으므로 사후 선택이 아니다.**
근거는 Phase 3 판정이며, Phase 3와 Phase 4는 별개 실험이다.

## 5. 설계 규율

### 5.1 강제 변이를 끈다
`no-change`(baseline이 지배당하지 않음)는 **정당한 산출**이다. 매 이터레이션
변이를 강제하지 않는다. 참조 구현의 `"Do NOT write 'the frontier is optimal'"`
지시는 **흡수하지 않는다** — 이는 Goodhart를 구조화한다.

### 5.2 데이터 분리
- 탐색·변이 생성에 **Phase 3 확증 집합을 쓰지 않는다.** 탐색 집합(371건)과
  Phase 1 라벨 55건만 쓴다.
- Phase 1 라벨 55건은 **성능축 측정 전용**이며 탐색 신호로 노출하지 않는다.
- 이 분리를 `phase4_split_check.py`가 실행 시 검증하고 위반 시 중단한다.

### 5.3 재현성
- 모든 채점 3판 다수결. 단일 실행 수치를 성능으로 보고하지 않는다.
- 모델 ID `claude-sonnet-4-6` 고정(alias 금지).
- fail-closed: 타임아웃·파싱 실패는 UNRESOLVED, 정상 통과 금지.

### 5.4 탐색 비용과 운영 비용의 분리
`eval_budget`(탐색에 쓴 콜 수)은 **산출 하네스의 운영 비용이 아니다.**
둘을 별도 필드로 기록한다. 섞으면 "탐색을 적게 한 쪽이 싸다"는 무의미한 결론이 나온다.

## 6. 금지 사항

- 결과를 보고 H1'/H2', 판정 기준, 목적 벡터, N을 바꾸는 것
- 비용축을 사후에 추가·제거하는 것 (§3에서 3축 고정, 토큰축은 데이터 없으므로 영구 제외)
- 스칼라 가중합으로 지배 판정을 대체하는 것
- 탐색 집합 결과를 확증 주장으로 승격하는 것
- Phase 3 결론을 Phase 4 결과로 덮어쓰는 것
- 변이 채택 건수를 KPI로 삼는 것 (Goodhart — `probe-graph` 대원칙 3)

## 7. 미리 밝히는 한계

- 성능축이 **Phase 1 라벨 55건**에 묶여 있다. 이 집합은 이미 여러 Phase에서
  참조됐으므로 완전히 신선하지 않다. 대안이 없어 쓰지만, 결론에 이 사실을 병기한다.
- 비용축이 프록시다. 프롬프트 문자수는 토큰의 대리이고 `elapsed`는 네트워크
  변동을 포함한다. **비용 차이가 작을 때는 판정하지 않는다** — 임계를 미리
  정한다: 프롬프트 문자수 ±5% 이내, `elapsed` ±20% 이내는 **동률로 처리**.
- 단일 도메인(K-IFRS), 단일 저지 모델. 일반화를 주장하지 않는다.
- meta-harness 코드를 재사용하는 경우 MIT 라이선스를 준수하고 출처를 명기한다.
  단 우리 기여는 코드가 아니라 **다목적 채택 게이트**이며, 표현 복제가 아니라
  공개 방법론 기반 자체 구현으로 간다.
