# 부속서 6 — E3: 판정기만 바꿔 탐색 여지를 확보한다

2026-11-23 · 상태: **E3 판정 0콜 시점에 커밋**. E2(부속서5) 결과는 열람했다(추기 5). 이 문서는 E2 의 판정·원자료를 바꾸지 않는다.

## 0. 왜
E2 는 계기 검침을 통과했지만 기준선(opus-5-5)이 recall 0.993 · specificity 0.980 으로 천장이라 탐색이 무엇도 보일 수 없다. 라벨셋·축·검침 규칙은 검증됐으므로 **변인 하나(판정기 모델)만** 바꾼다.

## 1. 불변 (부속서5 그대로)
SF-300(`sf300_label_set.json`, 운영자 검수 채택본) · 축 (recall, specificity) · 판정 프롬프트 c000(인용 번호 없음) · 3판 다수결 · R1~R6 · ci_qid · IC-0′ 임계(recall ≥ 0.30, CONTRADICTED ≥ 1) · IC-1′ r=0.35, PASS ⇔ ①②(③ 참고) · seed · 제안기 `claude-fable-5-2` · 후보당 900콜 · T2 9,000콜/조건.

## 2. 판정기 선정 규칙 (결과 보기 전 고정)
- 후보 순서: **① `claude-sonnet-5` → ② `claude-haiku-4-5`** (강한 모델 먼저. 두 모델 모두 1콜 응답 확인, 판정 내용 없음).
- 후보마다 c000 기준선 900콜(IC-0′)을 잰다. **채택 ⇔ IC-0′ PASS and (recall ≤ 0.95 or specificity ≤ 0.95)** — 3판 다수결 점값 기준. 첫 채택 모델에서 멈춘다.
- ①이 천장(두 축 모두 > 0.95)이면 원자료를 `archive_e3_<모델>/` 로 옮기고 추기를 커밋한 뒤 ②를 잰다. ①이 IC-0′ FAIL 이어도 같다.
- 둘 다 미채택 → "SF-300 은 시험한 판정기 모두에게 쉽다(또는 못 쓴다)"로 보고하고 E3 종료. 더 어려운 라벨셋은 새 부속서.
- 선정에 쓰는 것은 **기준선 수준뿐**이다(탐색 효과를 보고 고르지 않는다 — 탐색 콜 0 시점).

## 3. 채택 뒤
- 채택 모델의 c000 원자료로 IC-1′(0콜) → IC-2′. IC-1′ FAIL → "이 판정기에서는 해상도 부족" 보고, 탐색 안 함.
- IC-1′ PASS → 탐색 C2→C0→C1. 단 `mh_search` 의 E2 축 연결(슬롯·원장 경로)은 아직 없다 — 연결 코드와 그 검사를 **탐색 첫 콜 전에** 따로 커밋한다.
- 예산 상한: 기준선 최대 1,800 + 탐색 27,000 = **28,800 판정 콜**. 제안기 콜 별도 집계.

## 4. 실행
`MH_EXP=E3` (파일 접두어 `mh_e3_`, 판정기 = `mh_exp.JUDGE`). 호출 실패는 판정으로 적지 않고 중단(부속서5 추기 4-4). 원자료는 채점 전에 커밋.

## 5. 한계 (결과와 무관하게 미리)
- 판정기를 E2 천장을 **본 뒤** 골랐다. 그래서 선정 규칙을 수준 기준 하나로 고정했다.
- E3 결론은 채택 판정기에 한정된다. "약한 판정기의 프롬프트를 탐색으로 개선할 수 있는가"이지 opus-5-5 에 대한 주장이 아니다.
- 제안기(fable-5-2)가 판정기보다 강하다 — 이 비대칭도 보고에 적는다.
- recall < 0.6 이면 IC-1′ 검정력은 모의로 보장되지 않는다(부속서5 추기 3-4).
- SF-300 은 규칙 주입 오류라 실전 오류 분포와 다르다.

## 6. 추기 1 — 판정기 후보를 현행 세대로 교체 (2026-11-23, 운영자 지시, 채점 0건 시점)

- **시점**: sonnet-5 기준선을 140/900콜 받은 상태에서 중단했다. 이 140건은 **채점·집계·판정 열람을 하지 않았다**(확인한 것은 행 수, UNRESOLVED 0건, model 필드뿐). 원자료·원장·매니페스트는 `scripts/archive_e3_sonnet5_aborted_20261123/` 에 보존하고 어떤 판정에도 쓰지 않는다.

## 8. 추기 3 — 파서 규칙 고정 · 기준선 재측정 (2026-11-23, 운영자 승인, 재측정 0콜 시점)
- **사유**: 추기 2 (a) — 판정기가 JSON 을 두 번 쓰면(자기 정정) 파서가 실패해 UNRESOLVED 가 됐다. 이는 계기 결함이지 판정 품질이 아니다. 고치지 않으면 탐색이 "한 번만 쓰게 하는 프롬프트"를 개선으로 집계한다.
- **규칙(결과 보기 전 고정)**: 판정기 출력에서 `label` 키를 가진 유효한 JSON 객체를 앞에서부터 모두 찾고 **마지막 것**을 판정으로 쓴다. 유효한 객체가 하나도 없으면 종전대로 UNRESOLVED(따옴표·이스케이프로 깨진 출력은 복구하지 않는다). 객체가 하나뿐이면 종전과 결과가 같다. E2·E3 에만 적용(E1 경로 불변).

- **불변**: §2 채택 규칙과 후보 순서, IC-1′ r=0.35, 프롬프트(sha 40a57f397cc1), SF-300 라벨. 라벨 재검수(추기 2 (c))는 이 추기 범위 밖 — 라벨을 바꾸려면 별도 추기.

- **예산**: 기준선 몫 상한을 1,800 → 2,700콜로 올린다(종전 sonnet-5-5 900콜 포함, haiku-5-5 900콜 여유 유지).
