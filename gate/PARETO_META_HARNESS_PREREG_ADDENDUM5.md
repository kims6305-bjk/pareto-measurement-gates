## 2. 라벨셋 SF-300 — 정답을 구성 단계에서 정한다
- **원천**: `ab/ab_questions_FROZEN.json`(119문항)의 `evidence_paragraphs`. 문단 머리 `[NNNN … 문단 k]` 단위로 나누고, `다.` 로 끝나는 20~160자 문장을 원천 문장으로 쓴다. "다음과 같다"로 끝나는 목록 도입문은 제외한다.
- **생성기**: `gate/scripts/sf_build_label_set.py` (결정론, LLM 0콜). `SF_SEED = 20261123`. 원천 문장마다 `sha256(f"{SF_SEED}|{qid}|{문장}")` 순으로 정렬해 앞에서부터 아래 유형에 배정한다. **원천 문장 1개는 단위 1개로만 쓴다.**
- **유형과 구성 정답** (질문 = 원천 문항의 질문, 형제 주장 없음, 인용 = 원천 문단 머리):
  | 유형 | 건수 | 주장 | 근거 | 구성 정답 |
  |---|---|---|---|---|
  | S | 150 | 원천 문장 그대로 | 원천 문항 근거 전체 | S |
  | C-neg | 75 | 원천 문장의 술어를 규칙표로 부정(긍정↔부정 1회) | 원천 문항 근거 전체 | C |
  | I-swap | 38 | 원천 문장 그대로 | **다른 기준서 번호**의 문항 근거(결정론 선택) | I |
  | I-drop | 37 | 원천 문장 그대로 | 원천 문항 근거에서 **그 문장만 삭제**(남는 본문 ≥ 40자) | I |
- 부정 규칙표(생성기 상수): `…하지 아니한다/…하지 않는다 → …한다`, `…수 없다 → …수 있다`, `…수 있다 → …수 없다`, `…한다 → …하지 않는다`, `…된다 → …되지 않는다`, `…이다 → …이 아니다`. 규칙이 맞지 않는 문장은 C-neg 에 배정하지 않는다. 변형 문장이 근거에 그대로 있으면 버린다.
- **id**: `{원천 qid}-sf-{유형}{순번}` — `mh_objectives.Unit.qid = id.split("-")[0]` 이므로 **문항 군집 = 원천 qid**(I-swap 도 주장 원천 기준).
- **산출**: `gate/scripts/sf300_label_set.json`(정답지, `human_label`) — 이 파일이 E2 의 INV-2 대상이다. 기존 55건 시트는 **건드리지 않는다**.
- **운영자 표본 검수(블라인드)**: 생성기가 `sf300_review_sheet.xlsx` 에 유형별 층화 30건(S 10 · C 10 · I-swap 5 · I-drop 5, `SF_SEED` 결정)을 **구성 정답을 숨긴 채** 싣는다. 운영자가 S/C/I 를 적는다.
  - 불일치 건은 저자가 원문으로 판정한다(생성기 오류 vs 검수 오류).
  - **생성기 오류 ≤ 2/30** → 채택. 오류 건만 정답지에서 정정하고 커밋(채점 전).
  - **생성기 오류 ≥ 3/30** → SF-300 기각. 규칙을 고쳐 재생성·재검수. 그동안 받은 판정 원자료는 폐기(보존 이동)한다.
- **채점은 검수 채택 후에만** 한다. 판정 프롬프트는 정답을 담지 않으므로(라벨 블라인드) 측정은 검수와 병행할 수 있다. 저자는 채점 전 판정 원자료를 열람하지 않는다(진행 건수만 본다).

## 3. 목적 축 재선정 (정본 §3.6 · FAIL 분기)
- E1 FAIL 분기대로 **precision 을 판정 축에서 내린다**(참고 필드로 계속 기록).
- **새 축 = (recall ↑, specificity ↑).** `specificity = 구성 정답 S 중 다수결이 문제판정(C/I)이 아닌 비율` (SPLIT·UNRESOLVED 는 문제판정 아님 — §3.4 SPLIT 규약과 같은 방향).
- 왜 specificity 인가: 과검출을 벌하는 역할은 precision 과 같지만 **분모가 판정기와 무관한 고정값(S 150건)** 이다. E1 실패 원인 2(판정기 의존 분모 n_flagged 가 작아 CI 폭발)를 구조로 없앤다. recall 과 서로 밀당한다(전부 문제판정 → recall 1, specificity 0).
- §3.2 기각 목록(A3~A7)과 겹치지 않는다. 축 개수 2 유지(§3.6).
- 같은 55건으로 축을 고르지 않았다 — 축 선택은 SF-300 결과 0건 시점이다.

## 4. 판정 규칙
- dominance = **부속서4 건전 구간 지배**(모든 축 x 하한 ≥ y 상한, 한 축 초과). 판정 CI = ci_qid, B=2000, seed 20260730(불변). E2 가 이 규칙의 **첫 실사용**이다.
- 표본 요건 R1~R5 불변 + **R6: 구성 정답 S 수 ≥ 8**(specificity 분모).

## 5. 계기 검침 (순서 §8.3 그대로)
- **IC-2′** (0콜): `mh_objectives.py --selftest` — specificity 합성 검사 포함.
- **IC-0′** (c000 측정 900콜 = 300건 × 3판): recall ≥ 30% **and** CONTRADICTED ≥ 1.
- **IC-1′** (0콜 추가 — c000 원자료의 결정론 열화 3종):
  - 선택: 단위 id 마다 `h = sha256(f"{IC1_SEED}|{id}")`, `IC1_SEED = 20261124`. `int(h,16)/2**256 < r` 인 id 를 고른다. **정답 라벨을 보지 않는다.** 고른 id 는 3판 모두 같은 값으로 바꾼다.
  - `n_over` (과검출): 고른 id 의 판정을 INSUFFICIENT 로.
  - `n_under` (과소검출): 고른 id 의 판정을 SUPPORTED 로.
  - `n_both`: 같은 해시로 고른 id 중 `int(h[:8],16)` 짝수는 INSUFFICIENT, 홀수는 SUPPORTED 로.
  - **PASS ⇔** ① `cmp_axis(c000, n_over, specificity, ci_qid) = +1` **and** ② `cmp_axis(c000, n_under, recall, ci_qid) = +1` **and** ③ `dominates(c000, n_both, ci_qid)` (부속서4 규칙).
  - **열화율 r**: 측정 전, SF-300 실제 군집 구조 위의 합성 판정으로 검정력을 모의한다(`sf_ic1_power.py`). 가정 c000 ∈ {recall 0.6, 0.75, 0.9} × {specificity 0.75, 0.85, 0.95}, 칸마다 모의 40회. **r ∈ {0.15, 0.20, 0.25, 0.30} 중 최악 칸에서 ①·② 동시 성립률 ≥ 0.90 인 가장 작은 r** 을 채택한다. 넷 다 미달이면 0.30 을 쓰고 "검정력 미달 위험"을 결과에 명시한다. 모의 결과와 채택 r 은 **측정 시작 전에** 이 문서 §9 에 추기·커밋한다.
- 결정론 열화가 검침하는 것과 못 하는 것(미리 적음): 이 표본·이 CI 규칙이 **크기 r 의 실제 열화를 구별하는 해상도**를 갖는지 검침한다. 프롬프트 변이가 실제로 그 크기의 차이를 만드는지는 검침하지 않는다 — 그것은 탐색의 결과다.

### 추기 2 — SF-300 생성 규칙 확정 (2026-11-23, 판정 측정 0콜 시점)
독립 리뷰 2건(opus-5-5, gpt-6.2-sol/gpt1)이 §2 문서와 생성기 차이 및 정답 오염을 지적했다. 아래가 §2 를 **대체**하는 최종 규칙이다. 정본 = `gate/scripts/sf_build_label_set.py`.
1. **원천 확대**: 문단 머리 `[NNNN … 문단 k]` 와 `[문단 k]`(기준서 = 문항 `standard` 앞 4자리) 둘 다 인식. 원천 문장 306 → 필터 후 풀 247, 원천 문항 108.
2. **원천 문장 필터**: `다.` 로 끝나는 20~160자, 내부 개행·`#` 시작 제외, 앞머리 목록기호 `(1)` `1.` `가.` `(가)` 제거, `다음…다.` 로 끝나는 목록 도입문 제외, 문항 간 같은 문장은 qid 오름차순 첫 번째만.
3. **짝 설계**: 원천 문장 1개 → **S 1건 + 오류 1건** (§2 "1문장 1단위" 대체). 150쌍. 오류 유형 1순위는 해시 정렬 위치 기준 `C → Iswap → C → Idrop` 순환, 만석·부적격이면 `C, Iswap, Idrop` 중 남은 순서로, 셋 다 불가면 그 문장은 짝째 버림. 짝은 같은 원천 qid → `ci_qid` 군집 안에서 함께 재표집된다. 같은 문장이 specificity 분모와 recall 분모에 함께 들어간다는 의존은 해석 한계로 적는다.
4. **C-neg**: 규칙표(§2) + `되지 아니/않는다→된다`, `하여야/해야 한다→하지 않아야 한다`. 일반 `-어야 한다` 형, 술어 밖에 `못·아니·않·모두·어느 때·적어도` 가 있는 문장은 부적격(이중부정·범위 모호 차단).
5. **I-drop**: 주장 문장이 든 **문단 블록을 통째로** 삭제(빈 번호 등 흔적 방지). 남은 본문 `norm` 길이 ≥ 40 이고, 남은 문장마다 `주장 3-gram 중 그 문장에도 있는 비율` 의 최댓값 < **0.4** 일 때만 적격(재진술 잔존 차단).
6. **I-swap**: 교체 근거 문항의 기준서 집합(머리 + `standard`)에 원천 문장 기준서가 없고, 정규화 주장이 교체 근거에 없는 후보 중 `sha256(seed|swap|qid|문장|후보qid)` 최소.
7. **id**: `{원천 qid}-sf-{S|C|Iswap|Idrop}{유형별 3자리}`.
8. **검수 시트 블라인드**: 시트에 id 를 싣지 않는다(id 가 유형 노출). 번호↔id 는 `sf300_review_key.json` 에만. 같은 짝 두 건 동시 출제 금지. 층화 S10·C10·Iswap5·Idrop5, 층 내 `sha256(seed|review|id)`, 출제 순서 `sha256(seed|order|id)`.
9. **I-drop 전수 라벨 검수(판정 측정 전)**: 판정기(opus-5-5)는 라벨 정제에 쓰지 않는다 — 판정기가 맞힐 문제만 남기는 순환 오염 때문. 검수자 = `gpt-6-astra`(openai-codex). 실측(세션 기록상 실제 모델 확인): I-drop 37건 + 같은 짝 S 양성대조 12건 블라인드 혼합 → **I-drop 37/37 = I, 양성대조 12/12 = S**. 제외 0건. 검수자가 S 를 실제로 구별함을 확인.
10. **결과 라벨셋**: 300건(S 150 · C 75 · Iswap 38 · Idrop 37), 원천 qid 72. I-drop 은 19문항에 몰려 있어 **유형별 recall(I-swap/I-drop/C)은 참고값으로만 보고**하고 판정 축(recall 전체)은 불변.
11. **판정 프롬프트에서 주장 인용 번호 제거**: I-swap 은 인용(원천 기준서)과 근거 머리가 늘 어긋나 판정기가 내용 대신 번호로 맞힐 수 있다. E2 판정 프롬프트는 `claim_citation` 을 싣지 않는다.
12. **미결(추기 3에서 측정 전 확정)**: r 검정력 모의에 IC-1′ ③(dominates) 포함 여부, §6 27,900 이 판정 콜만인지(제안기 콜 별도 집계) 명시.
