# 옆방 검증 사전 선언 (Cross-Domain Instrument Check) — 실행 전 커밋

**이 문서를 커밋한 뒤에 실행한다.** 결과를 보고 기준·표본·정의를 바꾸지 않는다.

## 0. 무엇을 검증하려는가

README「도메인 이식성」절은 "스킬 본체와 게이트 절차에는 도메인 종속이 없다"고
**주장**한다. 그러나 이 레포의 모든 수치는 단일 도메인(K-IFRS) · 단일 저지 모델 ·
단일 라벨러에서 나왔고, 그래서 현재 범용성은 **미검증(unverified)**으로 표기돼 있다.

이 실험은 그 표기를 실측으로 대체하려는 시도다.

> **검증 대상은 프로브가 아니라 계기 검침(instrument check) 절차다.**
> "이 검침이 K-IFRS 밖에서도 도구의 신호 검출력을 판별하는가."

## 1. "같은 방"이 어디까지였는지 명시 (cross-domain validation §1)

지금까지 계기 검침을 통과시킨 데이터의 구성:

- **도메인**: 한국채택국제회계기준(K-IFRS) 공개 기준서 12종
- **언어**: 한국어
- **근거 형태**: 기준서 문단 (법률 문체, 조건 나열형)
- **라벨러**: 1인 (저자), 55건
- **판정기**: `claude-sonnet-4-6`, 3라벨 계약

즉 **언어·도메인·문체·라벨러가 전부 하나**다. 이 중 무엇 때문에 81.8%가 나왔는지
지금 데이터로는 분리할 수 없다.

## 2. 옆방 선정과 근거

**SciFact** (Wadden et al., EMNLP 2020, arXiv:2004.14500, CC BY-NC 2.0)

| 축 | 원래 방 (K-IFRS) | 옆방 (SciFact) | 다른가 |
|---|---|---|---|
| 언어 | 한국어 | 영어 | ✅ |
| 도메인 | 회계 기준 | 생의학 논문 초록 | ✅ |
| 문체 | 규범적 조문 | 실증 연구 서술 | ✅ |
| 라벨러 | 저자 1인 | 전문 어노테이터 (외부) | ✅ |
| 라벨 체계 | S / C / I | SUPPORT / CONTRADICT / NOINFO | 1:1 대응 |

**라벨러가 다르다는 점이 특히 중요하다.** 원래 방에서는 저자가 라벨하고 저자가
설계한 판정기를 검침했으므로, 라벨 기준과 판정기 기준이 무의식적으로 정렬됐을
가능성을 배제할 수 없다. SciFact 라벨은 이 프로젝트와 무관하게 만들어졌다.

**데이터 출처**: `https://scifact.s3-us-west-2.amazonaws.com/release/latest/data.tar.gz`
(`claims_dev.jsonl` 300건 + `corpus.jsonl` 5,183건). 라이선스 CC BY-NC 2.0 —
**비상업적 연구 목적 사용이며 원본 데이터를 이 레포에 재배포하지 않는다.**
다운로드 스크립트만 동봉한다.

## 3. 표본 구성 (실행 전 확정)

`claims_dev.jsonl`에서 기계적으로 구성한다. **선별하지 않는다.**

- 단위 = (claim, cited_doc) 쌍. dev 전체에서 321쌍 가용
  (S 138 / C 71 / I(NOINFO) 112, 문제 사례 비율 57.0%)
- **표본 크기 N = 55** — 원래 방과 동일하게 고정한다. 비교 가능성을 위해서다.
- **추출**: seed 20260728 고정 셔플 후 앞에서부터, 단 **라벨 층화**로
  S 33 / C 11 / I 11 을 채운다(원래 방의 S 44 / C 8 / I 3 과 문제 비율을
  맞추려는 것이 아니라, **문제 사례가 충분히 들어가도록** 보장하기 위함).
- 층화 비율은 **실행 전에 이 문서로 고정**하며 결과를 보고 바꾸지 않는다.

### 3.1 원래 방과 다른 점 — 미리 밝힌다

- 원래 방 55건의 문제 사례는 11건(20%)이었고, 여기는 22건(40%)이다.
  **따라서 두 recall 수치를 직접 비교하지 않는다.** 비교 대상은 수치가 아니라
  **판정(PASS/DEGRADED/FAIL)** 이다.
- SciFact의 근거는 초록 전문이 아니라 어노테이터가 지정한 **rationale 문장**이다.
  원래 방의 "기준서 문단"과 길이·구조가 다르다. 이는 도메인 차이의 일부로 간주한다.
- 형제 주장(siblings)이 SciFact에는 없다. 계기 검침은 조건 B(형제 포함)로 돌렸으나
  형제가 없으면 그 블록이 비므로, **여기서는 형제 없는 상태로 실행**된다.
  이것은 음성 대조군과 같은 조건이며, 원래 방에서도 단독 주장은 그렇게 돌았다.

## 4. 🔴 사전 선언한 판정 기준 (결과 확인 후 변경 금지)

원래 방과 **동일한 임계**를 쓴다. 임계를 옆방용으로 조정하면 검증이 무의미해진다.

| 판정 | 조건 | 해석 |
|---|---|---|
| **PASS** | recall ≥ 30% **and** CONTRADICTED 1건 이상 | 검침 절차가 도메인 밖에서도 작동 |
| **DEGRADED** | 0 < recall < 30% | 절차는 돌지만 검출력이 도메인 의존적 |
| **FAIL** | recall = 0 | 절차가 K-IFRS 전용 → **README 범용성 주장 철회** |

- recall = 사람 라벨이 문제(C 또는 I)인 건 중 판정기가 문제로 판정한 비율.
- 3판 다수결. SPLIT은 문제 판정으로 세지 않는다(원래 방과 동일).
- 정밀도는 보고만 하고 게이트에 쓰지 않는다(원래 방과 동일).

### 4.1 결과별로 무엇을 할지 미리 고정한다

| 결과 | README 「도메인 이식성」절 조치 |
|---|---|
| PASS | "미검증" 표기를 **실측 결과로 교체**. 두 도메인 판정표 병기 |
| DEGRADED | "미검증" 유지 + **"영어·생의학에서 검출력 저하 관측"** 명시 |
| FAIL | **범용성 주장 자체를 철회**하고 "K-IFRS 조건에서만 검증됨"으로 축소 |

어떤 결과가 나와도 **레포에 기록한다.** 실패해도 지우지 않는다.

## 5. 이 검증이 답하지 못하는 것

- 표본이 1개 도메인 추가일 뿐이다. PASS여도 **"모든 도메인에서 된다"가 아니라
  "두 번째 도메인에서도 됐다"**까지만 주장한다.
- 판정기 모델은 여전히 `claude-sonnet-4-6` 하나다. 모델 간 이식성은 미검증으로 남는다.
- SciFact 라벨도 완벽하지 않다(어노테이터 불일치가 원 논문에 보고됨).
  판정기가 놓친 건이 반드시 판정기의 실패는 아니다.
- **N=55는 검정력을 위한 크기가 아니라 원래 방과의 비교 가능성을 위한 크기다.**
  Wilson 구간을 함께 보고하며, 두 도메인의 recall 차이에 유의성 검정을 하지 않는다.

## 6. 비용

55건 × 3판 = **165콜**, 약 15분. 원래 방과 동일하다.

## 8. 🔴 두 번째 옆방 (KLUE-NLI) — SciFact 결과 열람 **전**에 선언한다

**이 절은 SciFact 결과를 보기 전에 작성·커밋됐다.** 커밋 순서가 git 이력으로
검증 가능하며, 이것이 "실패하니까 데이터셋을 갈아끼웠다"와 구별되는 유일한 근거다.

### 8.1 왜 필요한가 — SciFact만으로는 원인 귀속이 안 된다

§2의 표를 다시 보면 SciFact는 **언어·도메인·라벨러가 동시에** 바뀐다.
따라서 SciFact가 FAIL로 나와도 **무엇 때문인지 말할 수 없다.**
이것은 Phase 1 시도 3이 무너진 구조(문맥+지시 동시 변경 → 귀속 불가)와 같다.

| 표본 | 언어 | 도메인 | 라벨러 |
|---|---|---|---|
| 원래 방 (K-IFRS) | 한국어 | 회계 기준 | 저자 |
| 옆방 1 (SciFact) | **영어** | **생의학** | **외부** |
| 옆방 2 (KLUE-NLI) | 한국어 | **일상·위키·리뷰** | **외부** |

옆방 2는 **언어를 원래 방과 같게 고정**하고 도메인·라벨러만 바꾼다.
두 옆방의 판정을 대조하면 축이 분리된다:

- 옆방1 FAIL + 옆방2 PASS → **언어가 벽**이다 (한국어 프롬프트 ↔ 영문 근거)
- 옆방1 FAIL + 옆방2 FAIL → **도메인 일반화 자체가 안 된다**
- 둘 다 PASS → 범용성 주장이 두 축 모두에서 지지된다

### 8.2 이것은 교체가 아니라 추가다

**SciFact 결과는 PASS든 DEGRADED든 FAIL이든 그대로 보고하고 삭제하지 않는다.**
옆방 2는 그것을 대체하는 것이 아니라 원인 축을 분리하기 위해 더하는 것이다.
결과가 나쁘다고 옆방을 갈아끼우는 것은 optional stopping의 데이터셋판이며,
이 레포에서는 금지한다.

### 8.3 표본과 기준 (실행 전 고정)

- 데이터: **KLUE-NLI** validation 3,000행 (CC BY-SA 4.0, 원본 재배포 없음)
  - `premise` → 근거(evidence), `hypothesis` → 검증할 주장(claim)
  - 라벨 `entailment / neutral / contradiction` → **S / I / C** (1:1 대응)
- **N = 55**, seed 20260728, 층화 **S 33 / C 11 / I 11** — 옆방 1과 완전 동일
- 판정 임계 **recall ≥ 30% and CONTRADICTED ≥ 1건** — 원래 방·옆방 1과 동일.
  옆방별로 임계를 조정하지 않는다.
- 3판 다수결, SPLIT은 문제 판정으로 세지 않음, 판정기 프롬프트 수정 금지.

### 8.4 미리 밝히는 한계

- KLUE-NLI의 `premise`는 **한 문장**이라 원래 방의 "기준서 문단"보다 짧다.
  근거 길이가 짧으면 INSUFFICIENT가 늘어날 수 있다 — 결과 해석 시 병기한다.
- NLI는 "인용 검증"이 아니라 **함의 판정** 과제다. 스키마는 1:1이지만 과제 성격이
  다르므로, 옆방 2의 PASS는 "인용 검증이 일반화된다"가 아니라
  **"판정기가 한국어 비회계 도메인에서도 상충/불충분을 구별한다"**까지만 주장한다.
- 두 옆방의 recall 수치를 서로 직접 비교하지 않는다(§3.1과 동일 원칙).
  비교 대상은 **판정(PASS/DEGRADED/FAIL)** 이다.
