# 부속서10 — 구조가 다른 후보 c401 1개 대 c000 (2026-11-24, 결과 전 동결)

## §1 목적
부속서9 추기4: c301·c302(c000 문구의 근접 변형)는 c000 을 지배하지 못했다. 남은 빈칸 =
"판정 절차 자체가 다른 하네스와는 붙여본 적 없다". 후보 **1개**만 추가해 이 빈칸을 메운다.

## §2 후보 c401 (정본 = `scripts/sfk_e10.py` PARTS, 이 커밋에서 동결)
- 변경 표면: JUDGE.task · def_supported · def_contradicted · def_insufficient · closing (preamble 가드·CONTRACT·형제 문맥 유지).
- 절차: 주장을 조건(주체·대상·요건·예외·결과)으로 분해 → 조건별 근거 문장 대조 → 하나라도 반대면 C, 하나라도 없으면 I.
  근거가 기억과 달라도 근거를 따른다. 출력 JSON 앞에 `checks` 키 요청.
- 설계 근거로 본 자료: E6P 파일럿 유형별 집계(I-drop·Scf 약점)와 E5 오류 분석뿐. **E6 본측정 문항별 결과는 열람하지 않았다.**
- 형식 점검 1콜(파일럿 단위 0): 라벨 파싱 정상, 단 Haiku 는 `checks` 키 대신 rationale 에 대조를 적음
  (말미 CONTRACT 가 우선). 라벨 파싱엔 영향 없음 — 그대로 진행, 표면 추가 수정 없음.
- 알려진 한계: "근거가 기억과 달라도 근거를 따른다"는 v4 Scf 구성을 아는 상태에서 쓴 문장이다(설계 누설 위험).
  실사용에서도 타당한 일반 규칙이라 유지하되 해석 시 명시한다.

## §3 안전 게이트 (E6P 파일럿, 3판 × 200 = 600콜)
- c401 recall ≥ 0.70 **and** specificity ≥ 0.70 → 본측정 진행. 아니면 본측정 없이 중단·기록.
- 파일럿에서 c000 과의 Δ 는 계산하지 않는다(조정 유혹 차단). 게이트 뒤 표면 수정 금지.
