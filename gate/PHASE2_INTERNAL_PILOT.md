# Phase 2 내부 파일럿 설계 (사전 선언 — 라벨링 시작 **전** 커밋)

`PHASE2_LABELING_PROTOCOL.md` 의 부속 문서. 라벨 척도·QC·금지사항은 그 문서를
그대로 따르고, 이 문서는 **표본 크기 N을 어떻게 확정하는가** 하나만 정한다.

## 0. 왜 파일럿인가 — 해결하려는 충돌

Phase 2 확장 규모를 정할 때 세 목적이 서로 다른 것을 요구했다.

| 목적 | 요구 |
|---|---|
| 검증 최적합 | 문제 사례 55건 이상 (`phase2_power_analysis.py`) |
| 파레토 | 라벨 1건당 얻는 **독립** 정보 최대화 — 무조건 크게가 아님 |
| 논문 활용 | 사전등록 무결성 — 결과를 보고 N을 바꾸면 optional stopping |

문제는 필요한 N이 **기저율(문제 사례 비율)에 반비례**하는데 그 기저율을 모른다는
것이다. Phase 1 기저율 18.5%는 "저지가 시비 건 건 전수 + VERIFIED 표본"이라는
**편향된 추출**에서 나온 값이라 Phase 2 후보 풀(74문항 무작위)에 그대로 적용할 수
없다.

기저율을 모른 채 크게 잡으면 파레토가 깨지고, 작게 잡으면 검정력이 깨진다.
그래서 기저율만 먼저 읽는다.

## 1. optional stopping과 무엇이 다른가 (이 설계의 정당성)

- **금지되는 것**: 효과 지표(회수율, 정밀도, McNemar 불일치쌍)를 보고 N을 조정하는 것.
- **허용되는 것**: 효과와 무관한 **nuisance parameter**(여기서는 기저율)만 보고
  N을 조정하는 것. 이를 **internal pilot design**(Wittes & Brittain 1990)이라 부르며
  사전 선언 시 표준 기법으로 방어된다.

따라서 이 문서의 실효는 **"파일럿에서 무엇을 열람하는가"의 화이트리스트**에 있다.

### 1.1 파일럿 단계 열람 화이트리스트 (이것 외 전부 금지)

**열람 허용 — 사람 라벨에서 직접 세는 것만**
1. 문제 사례 수와 비율 `p̂ = (C + I) / (라벨 총수 − 명제없음)`
2. 문제가 걸친 서로 다른 답변 수(군집 계수)
3. 라벨 소요 시간(파레토 비용 항)

**열람 금지 — 파일럿 라벨과 대조하는 순간 블라인드가 깨진다**
- 프로브 출력(YES/NO), 저지 출력(라벨·사유), 회수율·정밀도·McNemar 어떤 형태로도
- 파일럿 구간에 한정한 게이트 성능 요약, 그 어떤 사전 집계도

이 화이트리스트는 결과를 본 뒤 확대하지 않는다.

## 2. 정본 순서(canonical order)와 중첩성

`phase2_build_pilot_sheet.py` 가 seed 20260728, CAP=3(SELECTION 면제)으로
**정본 순서 201건**을 한 번 생성하고 `phase2_canonical_order.json` 에 고정한다.

- **파일럿** = 정본 순서의 앞 30건
- **본 표본** = 같은 정본 순서의 앞 N건

파일럿은 본 표본에 **중첩(nested)** 되므로 폐기되지 않는다. 파일럿 라벨을 버리지
않으면서도 "결과를 보고 표본을 갈아치웠다"는 비판을 받지 않는 것이 이 구조의 목적이다.

**파일럿은 SELECTION 규칙을 앞으로 당기지 않는다.** R4(선택규칙 9문항 전량 포함)는
본 표본 수준의 요구이고, 파일럿의 유일한 임무는 **편향 없는 기저율 추정**이다.
특정 층을 앞으로 당기면 그 층의 문제 발생률이 추정치를 오염시킨다.

## 3. N 확정 규칙 (기계적 — 재량 없음)

파일럿 30건 라벨 완료 후 `phase2_determine_n.py` 가 아래를 그대로 계산한다.
사람이 개입하는 지점은 없다.

```
p̂    = (C + I 라벨 수) / (30 − 명제없음 건수)          # 점추정, CI 조작 없음
N_req = ceil(55 / p̂)                                   # 목표 문제 사례 55건
N     = clamp(N_req, 최소 90, 최대 201)                 # 201 = 정본 순서 전량
```

- **하한 90**: 기저율이 우연히 높게 나와도(예 p̂=0.6 → N_req=92) 군집화 목표
  "문제가 걸친 서로 다른 답변 25개 이상"을 만족하려면 최소한의 문항 수가 필요하다.
- **상한 201**: 후보 풀에서 만들 수 있는 전량. `N_req > 201`이면 **N=201로 두고,
  "목표 55건 미달 — 판정 불가 가능"을 결과에 명기**한다. 문항 증설로 넘어가려면
  별도 사전 선언을 새로 커밋한다(이 문서로는 못 넘어간다).
- p̂ = 0 이면 N=201 (분모 0 방지, 최대 확장).

참고 — 규칙 적용 결과 미리보기(기저율은 아직 모름, 규칙 자체는 여기 고정됨):

| p̂ | N_req | 확정 N |
|---|---|---|
| 0.15 | 367 | 201 (목표 미달 명기) |
| 0.20 | 275 | 201 (목표 미달 명기) |
| 0.27 | 204 | 201 (경계) |
| 0.35 | 158 | 158 |
| 0.50 | 110 | 110 |
| 0.60 | 92 | 92 |

즉 이 파일럿의 실질 결정은 **"전량 201로 가느냐, 그보다 줄이느냐"**이며,
줄일 수 있는 조건이 사전에 수치로 고정돼 있다.

## 4. 파일럿 단계에서 하지 않는 것

- 파일럿 라벨을 보고 라벨 척도(S/C/I 정의)를 손보지 않는다.
- 파일럿 라벨을 보고 후보 문항을 교체하지 않는다.
- 파일럿 결과가 마음에 안 든다고 시드를 바꿔 다시 뽑지 않는다.
- 파일럿 구간만으로 게이트 성능을 보고하지 않는다(표본 부족 + 블라인드 위반).

## 5. 실행 순서

1. 이 문서와 `phase2_build_pilot_sheet.py` 를 **먼저 커밋**한다. ← 방어의 조건
2. 파일럿 시트 `phase2_pilot_label_sheet.xlsx`(30건)를 bjkim이 라벨.
3. `phase2_determine_n.py` 실행 → p̂와 N을 기계적으로 산출, 원자료 커밋.
4. 확정된 N으로 `phase2_build_label_sheet.py` 를 정본 순서 앞 N건으로 잘라 본 시트 생성.
   파일럿 30건 라벨은 그대로 이월(재라벨 금지).
5. 본 라벨 완료 후에야 프로토콜 §4 QC와 효과 지표 집계로 넘어간다.

## 6. 한계 (결과와 무관하게 명시)

- n=30 기저율 추정은 표준오차가 크다(p̂=0.2일 때 ±0.07 수준). 그래서 N을 구간이
  아니라 점추정으로 정하되, **상한 201에 걸리면 "미달 가능"을 반드시 병기**한다.
- 파일럿·본 표본이 같은 라벨러(bjkim)이므로 학습효과로 후반 라벨이 달라질 수 있다.
  프로토콜 §4.1 재현성 표본(12문항 재라벨)이 이를 부분적으로 잡는다.
- 이 설계는 표본 크기 문제만 푼다. Phase 1에서 확인된 **군집화**는 R1(문항당 답변 1개)
  과 CAP=3로만 통제되며, 파일럿으로 해결되지 않는다.
