# 도달 분모가 없는 겨냥형 A/B는 효과 0을 식별할 수 없다

## 초록

특정 부분집합을 겨냥하는 검색·필터·안전 가드의 A/B에서 관측값 `0 → 0`은 두 상태를
동시에 표현한다. (1) 대상이 후보에 도달했으나 개입이 순위를 바꾸지 못한 **순효과 0**, 또는
(2) 질의가 대상에 닿지 않아 개입 기회 자체가 없었던 **겨냥 실패**다. 지표값만으로 두 상태는
식별 불가능하다. 본 노트는 질의별 후보와 대상 집합의 교집합으로 정의한 **도달 분모(reach)**를
최소 식별 통제로 제안하고, 운영 인용 파이프라인의 실제 고장 수리에서 그 필요성을 보인다.
가드 수리로 식별 대상은 0건에서 137,024건으로 늘었지만 일반 프로덕션 A/B는 모든 관련성
지표와 순위가 불변이었다. 전체 제목 풀에서 seed를 뽑은 첫 겨냥 실험도 0 → 0이었으나,
대상에서 seed를 뽑고 reach를 출력하자 20문 중 17문이 도달했고 대상 노출은 36 → 21로
변했다. 이 변화는 관련성 개선이 아닌 안전 프록시의 기계적 효과로 분리 판정했다.

## 1. 문제 정의

질의 집합을 `Q`, 질의 `q`의 상위 `k` 후보를 `R_k(q)`, 개입이 겨냥하는 대상 문서 집합을
`T`라 하자. 보통의 노출 지표는 다음과 같다.

```
E = Σ_q |R_k(q) ∩ T|
```

개입 전후 `E_before = E_after = 0`이면 흔히 “효과 없음”으로 판정한다. 그러나 `T`가 후보에
한 번도 들어오지 않았다면 개입은 평가받은 적이 없다.

## 2. 도달 분모

질의별 도달 지시함수와 도달 분모를 다음처럼 정의한다.

```
I_reach(q) = 1  if R_before,k(q) ∩ T ≠ ∅, else 0
Reach = Σ_q I_reach(q)
```

- `Reach = 0`: 겨냥 실패. 효과 방향을 판정하지 않는다(`NOT_MEASURED`).
- `Reach > 0`이고 노출·순위 모두 불변: 순효과 0(`NO_EFFECT`).
- `Reach > 0`이고 노출 또는 순위가 변함: 기계적 효과 확인(`MOVED`). 관련성 개선은 별도 gold로 판정한다.

Reach는 **개입 전 baseline 후보만**으로 정하고, 노출·대상 순서변동도 이 baseline 도달 질의에만
집계한다. 전후 합집합이나 미도달 질의의 ON 변화를 섞으면 ON이 대상을 새로 주입해 자기 측정의
유효성을 만들 수 있기 때문이다. 대상을 새로 회수하는 개입은 별도의 고정 eligibility 집합으로
평가해야 하며, 이 도구의 reach 계약에는 포함하지 않는다.

### 식별 명제

`E_before = E_after = 0`만 관측하면 겨냥 실패와 순효과 0은 관측적으로 동일하다.
`Reach`를 함께 관측하면 `Reach=0`과 `Reach>0`으로 두 상태가 분리된다. 따라서 reach는
겨냥형 A/B에서 “효과 없음”을 주장하기 위한 최소 필요 통제다.

## 3. 운영 사례

데이터 규약 변경으로 식별자가 본문 문자열에서 노드 속성으로 이동했지만 가드는 옛 정규식을
유지했다. 빈 집합이 fail-open으로 처리되어 모든 항목이 “근거 있음”으로 통과했다.
속성 조인으로 고친 뒤 식별된 대상은 `0 → 137,024`건이었다.

### 일반 프로덕션 A/B

| 지표 | 전 | 후 | 변화 |
|---|---:|---:|---:|
| recall@10 | 0.110 | 0.110 | ±0 |
| precision@3 | 0.051 | 0.051 | ±0 |
| Hit@3 | 0.154 | 0.154 | ±0 |
| 상위 10위 순서변동 | — | 0건 | — |

이 결과는 “회귀 없음”을 지지하지만 대상에 대한 효과를 측정했다고 보장하지 않는다.

### 겨냥 A/B

1차는 전체 제목 풀에서 seed를 뽑아 대상 도달이 거의 없었다. seed를 대상 집합에서 뽑도록
수정하고 reach를 선행 출력했다.

| 항목 | 결과 |
|---|---:|
| 질의 | 20문 |
| 도달 분모 | 17문 |
| 대상 노출 | 36 → 21 |
| 전체 상위 10위 순서변동 | 13문 |

## 4. 판정

- **기록 집계에서 관측됨**: 가드의 기계적 효과와 13문 프로덕션 표본의 회귀 미관측.
- **미증명**: 정답 관련성 개선. 관련성 지표는 ±0이었다.
- **최종 문장**: “13문 기록 집계에서 회귀는 관측되지 않았고, 품질 개선은 미증명, 안전 프록시는 회복으로 기록됨.”

## 5. 하네스 다이어트와의 연결

하네스 ON/OFF 두 점을 품질(높을수록 좋음)과 운영비(낮을수록 좋음)에 놓는다.

- ON이 OFF를 지배 → `KEEP`
- OFF가 ON을 지배 → `REMOVE`
- 둘 다 비지배 → 실패군에만 ON인 조건부 후보를 측정(`TEST_THIN`)
- reach=0 → `NOT_MEASURED`; 제거 근거로 사용 금지

이 원칙은 “하네스를 많이 붙일수록 안전하다”는 가정을 거부한다. 목적은 레이어 수가 아니라
**측정된 후보 중 파레토 최적 구성**이다. 실행기는 [`../gate/harness_diet.py`](../gate/harness_diet.py),
도달 검사는 [`../gate/reach_check.py`](../gate/reach_check.py)에 있다.

## 6. 한계

- Reach는 대상에 닿았는지만 보며 정답 관련성을 말하지 않는다.
- 대상에서 seed를 뽑은 겨냥셋은 효과 검출용이며 자연 트래픽의 발생률을 추정하지 않는다.
- 숫자는 한 운영 파이프라인의 관찰 사례다. 일반화 주장은 구조(식별 불가능성과 분모 통제)에
  한정하며 효과 크기 `36 → 21`을 타 시스템으로 외삽하지 않는다.
- 자동 삭제는 수행하지 않는다. 운영 목적함수와 허용 비용은 사용자가 정하고 최종 제거를 승인한다.
